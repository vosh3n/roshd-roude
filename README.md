# 🌱 ۲۶ رشد — سورس کامل پروژه

پروژه کامل سایت «۲۶ رشد» با ۱۷ پوسته (تم)، کوییز اولین ورود، سیستم مأموریت‌ها، ویدیوها، تکالیف، گواهی و تنظیمات — ساخته‌شده با **Next.js 16 + TypeScript + Prisma (SQLite)**.

## 🚀 راه‌اندازی سریع

### پیش‌نیازها
- **Bun** (پیشنهادی) یا Node.js نسخه ۲۰ به بالا
- macOS / Windows / Linux — روی همه کار می‌کند

### مراحل نصب

```bash
# ۱) نصب پکیج‌ها
bun install        # یا: npm install

# ۲) دیتابیس
# فایل db/custom.db همراه پروژه است و همهٔ کاربران/داده‌ها داخلش هست.
# اگر می‌خواهی از صفر شروع کنی (دیتابیس خالی):
bun run db:push    # یا: npx prisma db push

# ۳) اجرا
bun run dev        # یا: npm run dev
```

سایت روی آدرس `http://localhost:3000` بالا می‌آید. ✨

> **نکته:** فایل `.env` همراه ریپو است (`DATABASE_URL=file:../db/custom.db`) و مسیرها نسبی‌اند؛ یعنی بدون هیچ تغییری روی هر سیستمی اجرا می‌شود.

## 🩺 عیب‌یابی سریع

| علامت | دلیل | راه‌حل |
|---|---|---|
| موقع ورود/ثبت‌نام پیام «خطای سرور — Environment variable not found: DATABASE_URL» | فایل `.env` پاک یا جابه‌جا شده | یک فایل `.env` کنار `package.json` با خط `DATABASE_URL=file:../db/custom.db` بساز و سرور را ری‌استارت کن |

| خطای دیگر در ورود | — | از نسخه‌ی جدید، متن کامل پیام خطا حالا در خود صفحه و در ترمینال سرور نمایش داده می‌شود؛ همان را گزارش بده |

## 👥 افزودن ممبر و مدیریت دسترسی‌ها

هر کاربر یکی از این سه دسترسی را دارد:

| نقش | دسترسی |
|---|---|
| `student` (دانش‌آموز) | تجربهٔ کامل: مأموریت روزانه، آزمون تعیین سطح، ویدیوها، تکالیف، گواهی |
| `parent` (والد) | **فقط مشاهده**: پیشرفت همهٔ دانش‌آموزها + فایل تکالیف ارسال‌شده — هیچ دکمهٔ تغییری ندارد |
| `admin` (مدیر) | همه‌چیز + بخش مدیریت ویدیوها/تکالیف در منو + انتخاب دستی سطح |

همهٔ این کارها با یک اسکریپت از ترمینال (همان‌جایی که `npm run dev` می‌زنی) انجام می‌شود:

```bash
# ساخت دانش‌آموز جدید (نقش پیش‌فرض student است)
npm run user -- add ali_79 12345 "علی محمدی"

# ساخت حساب والد (فقط مشاهده)
npm run user -- add fatemeh_m 12345 "فاطمه رضایی" parent

# ساخت مدیر جدید
npm run user -- add parsa2 12345 "پارسا" admin

# تغییر دسترسی یک کاربر
npm run user -- role ali_79 parent

# تغییر رمز
npm run user -- passwd ali_79 56789

# حذف کاربر (پیشرفتش هم پاک می‌شود)
npm run user -- delete ali_79

# دیدن همهٔ کاربرها و نقش‌هایشان
npm run user -- list
```

> **نکته‌ها:**
> - رمزها با `scrypt` هش می‌شوند (دقیقاً مثل خود سایت)؛ هیچ رمزی به‌صورت خام ذخیره نمی‌شود.
> - روی ویندوز هم همین دستورها کار می‌کنند؛ فقط اگر خطای `npm run user --` گرفتی، مطمئن شو از **پوشهٔ پروژه** اجرا می‌کنی.
> - حساب والدِ ساخته‌شده با `parent/12345` و بقیهٔ والدین از قبل داخل دیتابیس هستند.
> - اگر نقش کسی را عوض کنی، از دفعهٔ بعد که لاگین کند اعمال می‌شود.

## 🔑 ورود با ایمیل + بازیابی رمز عبور

- در صفحهٔ ورود، فیلد اول **«نام کاربری یا ایمیل»** است؛ می‌توانی با هرکدام وارد شوی.
- لینک «رمزت را فراموش کردی؟» در صفحهٔ ورود هست؛ با ایمیلِ حساب، یک کد ۶ رقمی می‌گیرد و رمز جدید می‌سازد.
- هنگام ثبت‌نام فیلد **ایمیل (اختیاری)** هست و کاربران قدیمی هم می‌توانند از **تنظیمات → حساب کاربری → ایمیل بازیابی رمز** ایمیلشان را ثبت کنند.
- **سرویس ایمیل:** اگر SMTP در `.env` تنظیم نشده باشد، کد به‌صورت **حالت آزمایشی** در همان صفحهٔ بازیابی نشان داده می‌شود (تا پروژه بدون سرویس ایمیل هم کار کند). برای ارسال واقعی ایمیل (مثلاً با جیمیل) این را در `.env` تنظیم کن:

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=my.email@gmail.com
SMTP_PASS=xxxx xxxx xxxx xxxx   # از Google Account → Security → App Passwords
```

## 🤖 آزمون تعیین سطح

- آزمون دقیقاً **۱۲ سؤال چهارگزینه‌ای** است؛ دانش‌آموز فقط گزینه (الف/ب/ج/د) را کلیک می‌کند — چیزی برای تایپ نیست.
- **جریان آزمون سمت سرور کنترل می‌شود**: تعداد سؤال‌ها، نردبان دشواری (آسان ← پیشرفته) و نتیجهٔ نهایی قطعیِ سرور است؛ مدل هوش مصنوعی فقط سازندهٔ سؤال است — پس آزمون هرگز بعد از یکی‌دو سؤال تمام نمی‌شود.
- نام و پایهٔ دانش‌آموز هرگز پرسیده نمی‌شود؛ بعد از هر پاسخ بازخورد کوتاه (درست/غلط + توضیح یک‌جمله‌ای) نمایش داده می‌شود.
- زنجیرهٔ هوش مصنوعی: کلید OpenRouter (اگر در `.env` باشد) ← **Pollinations رایگان بدون کلید** ← سرویس داخلی؛ اگر هیچ‌کدام در دسترس نبود، **بانک سؤال پشتیبان** هر رشته به‌کار می‌رود تا آزمون وسط راه نایستد.

## ⚠️ نکتهٔ مهم دربارهٔ فایل‌های آپلودی

پوشهٔ `db/uploads` همراه پروژه است، اما **یک ویدیوی حجیم (~۶۷MB) برای سبک‌تر شدن فایل ZIP کنار گذاشته شده**. رکورد آن در دیتابیس موجود است؛ فقط خود فایل را باید دوباره از پنل مدیر آپلود کنی (یا آن ویدیو را حذف کنی).

## 🆕 فیچرهای جدید

### 🤖 آزمون تعیین سطح هوشمند
در صفحه «انتخاب سطح»، دانش‌آموز یک آزمون ساخت‌یافتهٔ ۱۲ سؤالی چهارگزینه‌ای می‌دهد: نوار پیشرفت، بازخورد بعد از هر پاسخ، تطبیق دشواری بر اساس عملکرد و در پایان کارت نتیجه (سطح ۱ تا ۴ مبتدی/پایه/متوسط/پیشرفته + تعداد پاسخ درست + اطمینان + جمع‌بندی شخصی‌سازی‌شده).

- **کنترل جریان سمت سرور:** موتور آزمون در `src/lib/assessment-quiz.ts` است — سرور سؤال‌به‌سؤال می‌سازد، پاسخ‌ها را خودش تصحیح می‌کند و بعد از ۱۲ پاسخ نتیجهٔ قطعی می‌دهد. تعداد/پایان آزمون به تصمیم مدل واگذار نشده است.
- **ارائه‌دهندهٔ مدل:** اگر `OPENROUTER_API_KEY` در `.env` باشد از OpenRouter استفاده می‌شود؛ در غیر این صورت Pollinations (رایگان) و سپس سرویس داخلی. خروجی مدل JSON سخت‌گیرانه پارس می‌شود و در صورت خرابی، بانک سؤال پشتیبان همان رشته جایگزین می‌شود.
- پرامپت‌های مرجع هر رشته در `src/lib/assessment-prompts.ts` است (متن مرجع: `docs/assessment-prompt-source.md`).
- وضعیت نیمه‌کاره در localStorage ذخیره می‌شود و بعد از رفرش ادامه پیدا می‌کند؛ اگر نشست سرور منقضی شده باشد، آزمون به‌صورت شفاف از اول شروع می‌شود.

### 👨‍👩‍👧 پنل اولیا (فقط مشاهده)
چهار حساب والدین ساخته شده است: **`parent` / `parent2` / `parent3` / `parent4` — رمز همه: `12345`**

والدین فقط می‌توانند ببینند، تغییر نمی‌توانند بدهند: پیشرفت مأموریت‌ها، رشته و سطح، نشان‌ها و استریک هر دانش‌آموز + لیست تکالیف ارسال‌شده و فایل‌هایشان. پیشرفت دانش‌آموزها به‌صورت خودکار (debounce ~۱.۵ ثانیه بعد از هر تیک) به سرور sync می‌شود.

- اسکیمای دیتابیس: ستون `role` روی User (`student|admin|parent`) + مدل `Progress`.
- ساخت دوبارهٔ حساب‌های والدین: `DATABASE_URL="file:../db/custom.db" bun prisma/seed-parents.ts`
- API ها: `POST /api/progress` (فقط دانش‌آموز) و `GET /api/parent/overview` (فقط والد/ادمین).

### 📱 بهینه‌سازی موبایل
هدر موبایل جمع‌وجور شد (~۵۷px)، تب‌ها اسکرولی، اهداف لمسی ≥۴۴px، جلوگیری از زوم iOS روی ورودی‌ها، پشتیبانی safe-area و حذف کامل اسکرول افقی در عرض ۳۲۰–۴۳۰px — بدون تغییر دسکتاپ و با حفظ هر ۱۷ پوسته.

## ☁️ مرورگر ابری Browserless (اختیاری)

برای اجرای خودکار مرورگر بدون نصب مرورگر روی سیستم، یک نمونهٔ حداقلی و قابل‌اجرا با **Playwright (`playwright-core`)** به مرورگر مدیریت‌شدهٔ [Browserless](https://browserless.io) وصل می‌شود.

1. توکن را از [داشبورد Browserless](https://browserless.io/account/) بگیر.
2. یک‌بار بسته را نصب کن: `npm install -D playwright-core` (یا `bun add -d playwright-core`).
3. در `.env` (که کامیت نمی‌شود) این خط را بگذار: `BROWSERLESS_TOKEN=توکن-خودت`
4. اجرا:

```bash
npm run browserless:check                                # صفحهٔ عمومی example.com
node scripts/browserless-smoke.mjs https://example.com/  # آدرس دلخواه
```

- اسکریپت `scripts/browserless-smoke.mjs` توکن را فقط از `BROWSERLESS_TOKEN` (یا `.env`) می‌خواند و هرگز چاپش نمی‌کند؛ `.env` در `.gitignore` است، پس هیچ توکنی داخل مخزن نیست.
- منطقهٔ اتصال پیش‌فرض `wss://production-sfo.browserless.io` است؛ برای منطقهٔ دیگر `BROWSERLESS_ENDPOINT` را در `.env` بگذار (مثلاً `wss://production-lon.browserless.io`).
- بدون توکن، اسکریپت با پیام روشن و کد خروج ۱ تمام می‌شود و بقیهٔ بخش‌های پروژه دست‌نخورده می‌مانند.
